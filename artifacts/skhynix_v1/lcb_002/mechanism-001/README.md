# Recorded memory and submission-format analysis

This is a read-only diagnostic of the completed Luna pilot. It makes no model,
grader, retrieval or memory-write calls and does not change primary outcomes.
The cohort remains all 24 paired VALID tasks. The ten OFF-missing/ON-solved
pairs are highlighted only as a descriptive subgroup; regressions and absent
exposure remain in the report.

`memory-examples-source-001.py` checks the final analysis and exposure audit,
the frozen implementation, terminal ON state/solve bindings, exact injected
view hashes and source TRAIN captures. It projects only source identifiers,
field names/types, integer trace anchors, hashes and literal keyword flags.
Source reflection prose, candidate code, problem/test contents and model
reasoning are not published. All consumed references are checked again after
analysis; differing existing outputs are refused.

```powershell
python artifacts/skhynix_v1/lcb_002/mechanism-001/memory-examples-source-001.py
```

The result `memory-examples-001.json` contains 36 recorded injections from
seven distinct TRAIN episodes into 23 of 24 targets. All seven injected views
retain numeric `trace_steps` examples in the nested JSON summary. Six sources
use `[2]`; source `abc327_a` uses `[11]`. Those values refer to source history,
not to the target's history. A target must use valid steps from its own history.

The narrative scan searches the eight literal substrings listed in the helper.
No matches were found in the seven source reflections' summary, applicability
or procedure prose. This does not prove the semantic absence of format advice.
The structured examples are observable independently of that keyword scan.

Stored injection ledgers alone cannot prove that an example preceded a
particular `finish` request. Delivery analysis must use session prompt packets
or earlier completed tool responses, and compare them with the start of that
finish request. Its own response is too late. Separate sessions must not be
treated as a single continuously visible model conversation.

Original native receipts seal event-log hashes but do not seal prompt-file
hashes. Saved prompts can be hashed now and linked to the frozen prompt-to-stdin
code path; they cannot be described as independently sealed original prompt
bytes. These evidence strengths must remain distinguishable.

The completed delivery audit is `timeline-002.json`, generated by
`timeline-source-001.py`. See [TIMELINE.md](TIMELINE.md) for the event parsing,
source guards, synthetic validation and evidence grades. The earlier local
`timeline-001.json` was a development snapshot; `timeline-002.json` is the
published final audit. A rerun must use a new output filename:

```powershell
python artifacts/skhynix_v1/lcb_002/mechanism-001/timeline-source-001.py --pilot data/skhynix_lcb_002/pilot-001 --exposure-audit artifacts/skhynix_v1/lcb_002/pilot-exposure-audit-001.json --output artifacts/skhynix_v1/lcb_002/mechanism-001/timeline-recheck.json
```

The ON cohort has 40 recorded finish attempts from 24 problems, not 40
independent problems. All 22 accepted attempts had a recorded same-session
memory delivery before request start; all 18 rejected attempts lacked such a
structured delivery. This is an observational association. Twenty of those
accepted attempts have an earlier tool response pinned by an original event
receipt, while two rely on retained prompt evidence. An empty direct memory
field does not rule out information paraphrased into L0 or handoff prose.

Even an example-delivery-before-valid-submission sequence does not by itself
prove internal copying or the unique causal contribution of that example.
The same episode also includes other experience, and independent OFF/ON runs
can vary. Removing or isolating format examples would require a separately
specified experiment; none is run by these diagnostics.
