# 학습 기록을 고정한 Codex 메모리 비교

후속 [검증 스킬 실험](SKHYNIX_CODEX_SKILL_EVALUATION.md)에서 실제 Gate B 승격과
L3 조회를 연결했다. 아래 내용은 스킬 승격 전의 native002 실행을 설명한다.

새 문맥의 Codex 에이전트가 문제를 풀고 기존 공식 SWE-bench grader가 패치를
채점한다. 별도 모델 API 클라이언트를 사용하지 않는다. Codex 자체 사용량은
발생하며 이 실행기에서는 정확한 토큰·비용을 측정하지 않는다.

[실제 실행 결과](../reports/SKHYNIX_CODEX_LEARNING_EVALUATION.md): 공식 채점
9/9회를 완료했고 세 조건 모두 2/3 해결했다. M2 주입은 총 3개, PDF 조회
주입은 0개였으며 해결률 차이는 0%p다.

## 이번 실행의 구성

기존 SymPy 23262 파일럿의 메모리 없는 풀이와 새 SymPy 23413 풀이를 학습
자료로 사용한다. SymPy 23534, 23824, 23950을 평가한다. 각 평가 문제마다
메모리 없음, 기존 M2 조회, PDF 기반 조회를 같은 모델·도구·예산으로 실행한다.

새 문제는 고정된 SWE-bench Verified 데이터에서 기존 개발·최종 평가·smoke
목록을 제외한 뒤, 23262보다 큰 SymPy 문제 번호를 오름차순으로 네 개
선택했다. 먼저 선택한 하나가 학습, 나머지 세 개가 평가다. 문제 본문이나
해결 결과로 난이도와 메모리 관련성을 선별하지 않았다. 따라서 관련 없는
메모리를 조회하거나 조회를 보류하는 경우도 평가 결과에 포함한다.

[추가 문제 목록](../configs/skhynix_v1/codex_002_manifest.json)은 기존 동결
파일과 별개다. 학습 기준 커밋이 평가 기준 커밋의 조상인지 실제 Git 이력으로
확인한다. 이는 코드의 시점 관계이며, 새 에이전트 패치가 과거에 upstream으로
병합됐다는 뜻은 아니다.

## 무엇을 학습하는가

학습 자료는 제출 패치의 해시, 도구 실행 기록, 공개 테스트 관찰, 공식 채점
영수증과 연결한다. 실제 `SkillMemoryStore.record_episode`로 Gate A 경험을
저장한다. 공식 해결과 공개 테스트 성공을 확인한 기록만 공유 저장소 지식에
포함한다. 경험은 원래 작업·작성 주체·버전 범위를 유지하며 평가 에이전트의
개인 경험으로 복사하지 않는다.

두 메모리 조건에는 같은 공유 지식 내용이 제공된다. 실제 검색 방식과 조회
결정은 각 controller가 수행한다. PDF controller의 JSON 포장 때문에 실제
주입 bytes는 다를 수 있으며 그대로 집계한다. 과거의 테스트 명령이나 풀이
해석은 현재 코드에서 다시 확인해야 하는 관찰 기록이다.

성공한 문제 두 개가 곧 검증 스킬 하나를 뜻하지는 않는다. 이번 학습에서는
공통 절차를 사전 선언하고 독립적으로 검증한 증거가 없으므로 L3 스킬을
승격하지 않는다. **이번 비교는 실제 학습에서 얻은 저장소 지식의 전이 효과를
측정하며, L3 스킬이나 전체 PDF 구조의 효과를 측정하지 않는다.**

## 실행 순서

1. 추가 문제 목록과 이미지 digest를 고정하고 각 환경을 확인한다.
2. 새 학습 문제를 빈 메모리의 에이전트가 풀고 공식 채점한다.
3. 학습 자료를 검증해 메모리 bank를 만들고 그 파일의 SHA-256을 고정한다.
4. 평가 문제마다 별도 실행 디렉터리에 A/B/C 작업공간을 준비한다.
5. 모든 평가 작업이 아직 시작되지 않았는지 검사하고 전체 비교 계획을 고정한다.
6. 문제×조건마다 새 에이전트를 실행하고 제출 후 공식 채점한다.
7. 모든 공식 결과가 있어야 해결률 차이를 계산한다. 실패한 풀이도 분모에 남긴다.

준비·평가 CLI는 [기존 사용법](SKHYNIX_CODEX_PILOT.md)을 따른다. 새 실행에서는
`prepare`에 `--target-id`, `--experiment-id`, `--solver-user-id`,
`--supplemental-manifest`, `--frozen-memory-bank`를 추가한다. 작성 주체 ID는
실험의 에이전트 식별자이며 독립적인 사람의 참여를 뜻하지 않는다.

메모리 고정은 `scripts/trimem_skhynix_codex_learning.py`의 `--spec`과
`--output`을 사용한다. 전체 비교 계획 고정과 집계는
`scripts/trimem_skhynix_codex_batch.py freeze` 및 `aggregate`를 사용한다.
기존 실행 디렉터리를 초기화해서 재사용하지 않는다.

## 해석 범위

문제 세 개의 1회 실행은 작은 탐색 실험이다. 일반적인 해결률이나 속도 우위로
확대 해석하지 않는다. Codex 기본 문맥을 사용하므로 PDF의 L0 문맥 투영은
재현하지 않는다. 평가 중 메모리를 학습하거나 검색 임계값을 조정하지 않는다.

공개 명령은 별도 checkout과 고정 컨테이너에서 실행한다. 새 에이전트가
상속한 호스트 도구 전체를 OS 수준에서 차단하지는 않는다. 지정 중계기만
사용하도록 공통 지침을 주고 기록과 자기 확인을 보존한다. 이 절차의 준수와
강제 OS 격리를 구분해 보고한다.
