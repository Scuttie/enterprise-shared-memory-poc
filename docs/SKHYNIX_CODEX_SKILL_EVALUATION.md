# 실제 회귀 검증 절차를 학습하는 Codex 평가

[실제 실행 결과](../reports/SKHYNIX_CODEX_SKILL_EVALUATION.md): Gate B 스킬 1개를
승격했고, 새 평가 3문제의 공식 채점 9회를 완료했다. 세 조건 모두 3/3 해결이며
해결률 차이는 0%p다. PDF 조건은 세 번 모두 L3 스킬을 주입했다.

이 실행은 새 Codex 세션이 만든 패치와 공개 도구 기록을 사용한다. 별도 모델 API를
호출하지 않으며, Codex 자체 토큰·비용은 현재 실행기에서 관측하지 못한다.

## 학습과 평가 분리

이전 학습 SymPy 23262·23413을 보존하고 새 학습 24066·24213을 추가한다.
평가는 새로운 24443·24539·24562다. 기존 개발·최종 평가·smoke 및 이전 네이티브
실험 문제를 제외한 뒤 공개 문제 식별자의 순서로 선정했다. 기존 최종 평가 목록을
대체하는 실험은 아니다.

## 무엇을 검증 스킬로 만드는가

승격 대상은 **공개 회귀 테스트의 수정 전 실패와 수정 후 통과를 확인하는 절차**다.
특정 버그를 일반적으로 고치는 능력을 검증했다고 해석하지 않는다.

1. 수정할 구현 파일과 기존 공개 테스트 모듈을 읽는다.
2. 코드를 수정하거나 명령을 실행하기 전에 파일 경로와 테스트 명령을 등록한다.
3. 구현을 그대로 두고 새 assertion 회귀 테스트를 추가한다.
4. 등록한 명령으로 새 회귀 테스트의 `AssertionError`를 확인한다.
5. 테스트 파일은 유지하고 등록한 구현 파일을 수정한다.
6. 같은 명령의 성공을 확인하고 그 상태의 패치를 제출한다.

중계기는 테스트 실행 전후의 구현·테스트·테스트 실행기와 전체 패치 해시를 기록한다.
검증기는 실제 도구 기록에서 각 단계를 확인하며, 최종 통과한 코드와 제출한 코드가
같은지도 검사한다. 타임아웃·구문 오류·의존성 오류는 재현 성공으로 인정하지 않는다.

두 작업의 공식 채점 성공과 위 절차의 독립적인 실행 증거가 모두 있어야 실제
`SkillMemoryStore.record_episode()`와 `promote_skill()`을 호출한다. 서로 다른
Codex 세션의 식별자는 서로 다른 사람의 참여를 의미하지 않는다.

## 다른 코드 버전에서 제공하는 범위

원래 학습 경험의 작성 주체와 코드 버전은 보존한다. 기존 저장소의 버전 무효화
규칙을 수정하지 않는다. 공유된 절차는 별도 읽기 전용 투영에서 제공하며,
평가 기준 코드의 공개 테스트 실행기 해시, Python 버전과 기본 공개 테스트 실행을
별도로 확인한다. 이 확인은 테스트 절차의 실행 조건만 확인하며 평가 버그의 수정
정답이나 모든 입력 조건에 대한 검증을 뜻하지 않는다.

승격 authority와 공개 내보내기의 해시는 고정한다. 변경 또는 폐기된 원본을 감지하면
계속 조회하지 않는다. 개인 지원 경험의 원문은 평가 에이전트에 제공하지 않는다.

기존 M2는 공유 절차를 의미 기억으로 조회하고 PDF controller는 L3 스킬로 조회한다.
두 조건에 제공하는 공개 절차 내용은 동일하다. 메모리 없는 조건과 함께 같은 모델,
도구 요청 120회·1,200초, 최대 주입 3개·12,000 bytes로 비교한다. 평가 중에는
메모리나 조회 임계값을 수정하지 않는다.

초기 조회는 짧은 실제 문제 하위 목표와 공개 회귀 검증 작업으로 구성한다. 이 질의
형식을 모든 조건에 동일하게 적용하고 실행 전에 고정한다. 이전 실험과의 숫자 차이를
스킬 하나의 효과라고 해석하지 않는다. 새 표본 안에서 조건별 결과를 비교한다.

## 실행 도구

- `scripts/trimem_skhynix_codex_procedures.py declare`: 학습 전 절차와 학습 대상 고정.
- `scripts/trimem_skhynix_codex.py prepare --procedure-declaration`: 학습 실행 준비.
- 중계기의 `begin_procedure`: 첫 수정·명령 전 매개변수와 초기 파일 상태 등록.
- `scripts/trimem_skhynix_codex_procedures.py promote`: 실제 기록 검증 및 Gate B 승격.
- `scripts/trimem_skhynix_codex_learning.py`: 과거와 새 학습의 공개 관찰 기록 고정.
- `scripts/trimem_skhynix_codex_skill_bank.py`: 승격 결과와 실행 조건을 결합한 평가 은행.
- `scripts/trimem_skhynix_codex_batch.py`: 평가 시작 전 전체 계획 고정, 공식 결과 집계.

항상 새 실행 디렉터리를 사용한다. 원래 실행 위치는
`/home/trimem-runner/skhynix-codex-003`이다. 평가 풀이에는 학습 전용 절차 안내를
직접 넣지 않는다. 메모리 조회로 받은 내용만 해당 조건의 입력에 추가된다.

Codex 기본 문맥을 사용하므로 PDF의 L0 하위 목표 문맥 교체를 재현하지 않는다.
호스트 도구 접근 제한은 공통 지침과 실행 기록으로 관리하며 OS 격리의 증명은 아니다.
