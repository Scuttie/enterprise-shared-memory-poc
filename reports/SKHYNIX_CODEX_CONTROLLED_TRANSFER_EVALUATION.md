# SKHYNIX 다른 문제의 교훈을 직접 전달한 비교 평가 — Native011

다른 문제에서 얻은 관련 교훈 조건에서 기준선보다 더 많은 문제를 해결했다. 이 네 문제에서 관측한 상승이며, 조건별 한 번씩의 작은 탐색 실험이므로 일반적인 성능 향상이나 재현성을 확정하지 않는다.

SymPy 15875에서는 관련 교훈 조건만 공식 채점을 통과했다. 제출된 공개 패치를 비교하면 C는 실수부가 0인 해당 분기에서 허수항이 하나일 때만 확실히 0이 아니라고 판정하고, 여러 항이 상쇄될 수 있으면 판단을 보류하도록 수정했다. A/B는 허수항들의 합을 다시 계산해 0 여부를 판정하는 수정을 했다. 이는 관측한 구현 차이이며, 개별 수정과 공식 통과 사이의 인과효과를 분리해 검증한 결과는 아니다. 다른 문제에서 온 교훈과 결과가 함께 관측됐다는 근거로 해석한다.

교훈의 출처는 Native007의 SymPy 20428·20438 실패 기록과 공개 진단이다. 별도 작성자가 새 평가 문제를 읽기 전에 이 출처만으로 두 교훈을 작성했다. 두 본문은 각각 1,670 ASCII/UTF-8 바이트이며 단어 수는 231·240개다. 모델 토큰 수는 맞추거나 계측하지 않았다. 교훈은 자동으로 승격한 검증 스킬이 아니라 분석자가 정리한 진단이며 Gate B 승격은 0이다.

평가 문제 네 개는 출처 문제, 기존 Native 등록, 원래 DEV·heldout·smoke 분할 및 알려진 개발 문제와 겹치지 않는다. 공개 문제 설명을 보고 원인과의 관련성을 가정해 선택했으며 정답 패치나 비공개 테스트, 실제 풀이 결과는 선택에 사용하지 않았다. 관련성의 강도는 문제마다 다르고, 무작위 표본이나 난도가 입증된 표본은 아니다. 이 저장소는 이전에 조사했으므로 모델에 전역적으로 처음인 문제라는 주장도 하지 않는다.

각 문제에서 A는 빈 기록, C는 해당 분야의 교훈, B는 반대 분야의 교훈을 받는다. B도 일반적인 검증이나 기호식 주의를 포함하므로 관련성이 완전히 0이라고 보장하지 않는다. 따라서 B는 분량을 맞춘 다른 분야의 대조 조건으로 해석한다. 교훈이 일부러 관련 없다고 솔버에게 알려 주지는 않았다.

모든 조건은 먼저 공개 문제를 받고 유효한 recall을 해야 코드 도구를 사용할 수 있다. 첫 recall에서 A는 빈 결과, B/C는 사전에 배정한 교훈을 정확히 한 번 받는다. 단어 유사도 점수를 통과할 필요가 없고 이후 조회에는 본문을 반복 전달하지 않는다. 이는 교훈 내용의 효과를 분리하는 비교이며 자동 검색, 온라인 학습, 전체 PDF 메모리 구조의 종합 평가는 아니다.

평가 문제의 기준 커밋은 교훈 출처보다 오래됐다. 따라서 시간순으로 미래 문제를 해결하는 운영 시뮬레이션이 아니라, 서로 다른 과거 문제 사이의 회고적 전이 실험이다.

문제마다 A/B/C 한 번씩 총 12개 새 세션을 요청했다. 모델은 gpt-6-astra, fork_turns=none으로 요청했고 공통 지시문을 유지했다. 세션당 broker 요청 120회, 첫 요청부터 1,200초, 기록 최대 3회·12,000바이트의 동일한 상한을 적용했다. 평가 중 교훈·문제·지시문 수정, 결과를 본 풀이 재시도, 추가 힌트, 실패 제외를 하지 않았다. 실제 도구 사용량은 조건마다 다를 수 있다.

동시에 활성화된 broker 세션은 최대 2개이며, 한 문제의 세 조건이 끝난 뒤 다음 문제로 이동했다. 플랫폼에서 세션 생성 전에 거절한 시작 요청과 준비 단계의 오류는 운영 기록에 보존했다. 세션 생성 전의 재요청은 모델 풀이 재시도에 포함하지 않는다. 각 조건의 실제 제출과 공식 채점은 한 번씩이다.

검증은 데이터 등록·호환성 218개, 전달 경로·기존 broker 188개를 통과했다. 별도 합성 사전 검사 12개에서 실제 솔버 요청 0회를 확인한 뒤 실행했다. 최종 무결성 검사는 14,420개를 통과했고 이전 공개 기록 708개와 원본·복사본 1,420개 경로를 보존했다.

준비 단계에서는 부분 Git 기록의 누락 파일 때문에 공개 기준 커밋의 소스 압축 파일을 별도로 확보했다. 초기 등록 검사는 새 테스트 도구의 소문자 도움말 형식을 거절해 멈췄고, 기존·새 형식을 모두 검증하도록 수정한 뒤 실제 네 환경의 기록과 검사를 통과했다. 첫 초기화의 부분 기록을 보존했으며 당시에는 평가 manifest·소스 동결·솔버·공식 채점이 생성되지 않았다.

별도 모델 API 호출은 0이고 Codex 토큰·비용은 계측하지 않았다. 새 문맥과 모델은 요청한 설정이며, 호스트 접근 제한은 broker 기록과 솔버의 자기 확인에 근거한다. 이는 백엔드 모델이나 OS 수준 격리를 독립적으로 증명하지 않는다.
