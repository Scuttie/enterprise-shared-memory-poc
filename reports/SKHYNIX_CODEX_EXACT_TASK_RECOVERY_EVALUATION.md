20438의 같은 공식 테스트 항목이 메모리 조건의 두 새 세션에서 모두 통과했다. 각 기준선에서는 해당 항목이 오류였으며, 남은 항목은 양쪽 모두 실패했다. 비공개 이름이나 내용을 공개하지 않고 상태별 식별자 해시를 비교해 확인했다.

Native008에서 진단 메모리를 받은 두 세션은 전달받은 공개 사례를 구현하고 테스트했지만 문제 전체를 해결하지 못했다. 나머지 두 메모리 세션은 기록을 받지 못했다. 이번에는 같은 진단 내용을 유지하고, 정확히 같은 문제의 기록을 직접 조회하는 조건을 비교한다.

조회 변경은 `KNOWN_FAILURE_RECOVERY`에만 명시적으로 적용한다. 출처와 대상의 문제 ID·저장소·기본 커밋·공개 문제 설명이 모두 일치하고 검증된 기록에 한해, 단어 유사도 문턱을 거치지 않고 직접 연결한다. 실제 유사도 점수는 높여 쓰지 않으며 전체 내용과 출처, 범위·무효화·문맥 예산 검사는 유지한다. 기본 조회와 다른 문제로의 전이 정책은 바꾸지 않는다.

출처는 완료된 Native007 실패 A 에피소드 두 개와 기존 공개 진단이다. Native008·009의 공개 결과는 이번 조회 설계에 사용했지만 진단 내용을 추가하거나 수정하지 않는다. Gate A에는 실패 출처를 기록하고 Gate B 승격은 0이다. 자동으로 검증한 성공 스킬 평가가 아니다.

조건을 고정한 뒤 모든 여덟 세션을 한 번씩 제출·공식 채점한다. 결과를 본 재시도, 지시문·메모리 수정, 추가 힌트, 실패 제외는 하지 않는다. 사전 합성 조회와 실제 솔버에게 전달된 기록은 별도로 집계한다.

두 문제의 반복이므로 네 관측을 서로 다른 새 문제 네 개로 해석하지 않는다. 과거 Native008과의 차이에는 새 솔버 세션의 변동도 포함되므로 조회 정책만의 인과효과로 단정하지 않는다. 같은 실험에서 평가한 A/C의 결과와 실제 기록 전달을 함께 보고한다.
