# 학습 메모리를 고정한 Codex Astra 평가

**학습 2문제의 기록을 고정하고, 별도 평가 3문제 × 3조건의 공식 채점 9회를 완료했다.**

세 조건 모두 **2/3 해결(66.7%)이며, 메모리에 의한 해결률 상승은 이번 표본에서 0%p**다. 문제 세 개의 단일 실행이므로 일반적인 성능 차이로 확대 해석하지 않는다.

도구 요청은 검색·읽기·수정·명령·조회·제출·오류를 모두 포함한다. 한 문제당 한 번씩만 실행했고 배정 시점과 병렬 부하가 달라, 요청 수와 풀이 시간으로 안정적인 효율 우위를 주장하지 않는다. 해결 판정은 제출 후 기존 공식 SWE-bench grader가 수행했다.

**PDF 조건은 세 문제 모두 메모리를 주입하지 않았다.** 따라서 해당 조건의 성공을 메모리 도움으로 해석할 수 없다. M2는 세 번 주입했지만 해결률은 같았고 요청 합계는 더 많았다. 이 작은 표본만으로 M2가 일반적으로 해롭다고 단정하지 않는다.

## 실패한 문제에서 확인한 점

SymPy 23950은 세 조건 모두 공개 테스트를 145~146개 통과했지만 공식 평가에서 실패했다. 공식 패치는 정상 적용됐고 인프라 장애는 없었다. 기존 유지 검사 4개는 통과했으나 새 요구사항 검사 1개가 실패했다.

세 풀이 모두 **집합에 기호가 들어 있는 경우의 membership 변환**을 지원하지 못해 `NotImplementedError`를 냈다. 추가한 회귀 검증은 이 기호 집합 조건을 놓쳤다. 실패 원인 분석은 모든 평가 풀이가 제출된 뒤 수행했으며, bank나 제출물을 수정하거나 재채점하지 않았다. [실패 진단과 원본 증거 해시](../artifacts/skhynix_v1/codex_002/failure-diagnostics.json)를 보존했다.

## 학습과 평가를 어떻게 분리했나

학습은 이전 네이티브 파일럿의 메모리 없는 SymPy 23262 풀이와, 이번에 새로 실행한 빈 메모리의 SymPy 23413 풀이를 사용했다. 두 풀이 모두 공식 채점을 통과했다. 새 학습에서는 관련 공개 normal-form 테스트 6개도 통과했다. 학습 결과는 평가 해결률의 분모에 넣지 않았다. 준비된 학습 B/C 작업공간은 실행하지 않았다.

새 문제는 고정된 SWE-bench Verified 데이터에서 기존 개발·최종 평가·smoke 목록을 제외하고, 23262보다 큰 SymPy 문제 번호를 오름차순으로 네 개 선택했다. 첫 문제가 학습, 나머지 세 개가 평가다. 선정 시 문제 본문·정답·비공개 테스트·풀이 결과를 사용하지 않았다. 기존 최종 평가 목록은 소비하지 않았다. 실제 Git ancestry 7건으로 학습 기준 코드가 평가보다 앞서는 것을 확인했다.

새 평가 문제는 이번 학습과 분리돼 있지만 전체 벤치마크의 무작위 표본은 아니다. 기존 파일럿을 보고 SymPy와 이후 문제를 선택한 탐색 설계이며, 원래 사전 등록한 heldout endpoint나 리더보드 결과를 대체하지 않는다.

## 실제 저장·조회된 메모리

실제 Gate A 저장 경험은 **2개**, 공유 저장소 지식은 **2개**다. 원래 작업·작성 주체·버전 범위의 개인 경험은 보존하고, 평가 에이전트의 개인 경험으로 복사하지 않았다. 공유 내용에는 학습 문제의 공개 설명 일부, 관찰한 경로, 성공한 공개 테스트 명령·결과, 출처 해시와 풀이 해석이 들어간다. 풀이 해석의 모든 문장을 공식 테스트가 검증한 것은 아니며, 현재 코드에서 다시 확인하라는 조건을 함께 전달했다.

원본 제출 패치 내용과 grader 전용 테스트 내용은 bank에 넣지 않았다. 두 메모리 조건에는 같은 공유 지식 bytes를 제공하고, 실제 M2 controller와 `SkillFirstMemoryController`가 각각 조회를 결정했다. PDF controller의 JSON 포장 때문에 주입 bytes는 다를 수 있다. 조회가 기권한 경우도 그대로 결과에 포함했다.

**L3 검증 스킬은 0개다.** 공통 절차의 사전 선언과 독립적인 실행 검증이 없어 성공 사례만으로 Gate B 승격을 만들지 않았다. L2 지식 간선도 0개다. 따라서 이번 결과는 학습에서 얻은 저장소 지식의 전이 비교이며, 검증 스킬·KG·전체 PDF 구조의 효과를 보여주지는 않는다.

## 고정한 조건과 실행 경계

- 모델 요청: `gpt-6-astra`, 동일한 부모 reasoning 설정. 내부 날짜별 snapshot은 별도로 증명하지 못했다.
- 문제×조건마다 `fork_turns="none"`의 새 에이전트와 별도 초기 checkout을 사용했다. 다른 조건의 풀이 힌트를 전달하지 않았다.
- 예산: 각 조건 도구 요청 120회·첫 요청부터 1,200초. 하위 작업별 제한은 없다.
- 메모리: 작업당 최대 3개·12,000 UTF-8 bytes. 평가 전에 bank와 9회 계획을 고정했고 평가 중 메모리·검색 임계값을 바꾸지 않았다.
- 새 학습 및 평가 이미지 4개는 digest로 고정했다. 각 이미지에서 공개 기본 테스트 22개를 실행 전 통과했다.
- 별도 모델 API 호출 **0회**. Codex 자체 사용량은 발생하지만 토큰·비용은 관측하지 못해 `null`로 기록했다.
- Codex 기본 문맥을 사용한다. 기존 런타임의 L0 하위 목표 문맥 투영은 적용하지 않았다.

명령은 비관리자·네트워크 차단 컨테이너에서 실행한다. 새 에이전트가 상속하는 호스트 도구 전체를 OS 수준에서 막지는 않았다. 지정 중계기만 사용하도록 공통 지침을 주고 에이전트의 자기 확인 및 실제 중계 기록을 보존했다. 기록되지 않은 호스트 활동이 없었다는 강제 격리 증명은 아니다.

학습과 조회 연결, 추가 문제 선정·환경, 중계기·집계의 통합 검사 163개가 통과했다. 최종 집계 검사 25개도 통과했다(통합 검사와 중복 포함). 기존 동결 파일 651개 검사도 통과했다. 독립 감사는 **2,409개 검사 통과·실패 0개(PASS_FINAL)**다. 이는 실행 기록의 일관성 확인이며 실패한 풀이를 성공으로 바꾸는 판정은 아니다.

## 다음에 할 일

이 실행 방식은 사용자가 API 키를 설정하거나 세션을 하나씩 열 필요 없이 관리할 수 있다. 현재 구현은 대상 선택·학습 기록 고정·새 에이전트 풀이·공식 채점·전체 비교까지 연결한다.

다음 실험에서는 공통 절차를 학습 전에 선언하고 서로 다른 학습 작업에서 실제 검증한 뒤 Gate B 스킬을 만들 필요가 있다. 학습 자료의 크기와 종류도 늘리고, 평가 결과를 보고 해당 bank나 검색 기준을 다시 조정했다면 새로운 평가 문제를 선택해야 한다. 해결률뿐 아니라 실제 주입 여부, 잘못된 조회, 도구 사용량을 함께 비교한다.
