# 실제 검증 스킬을 고정한 Codex Astra 평가

**새 학습 2문제에서 실제 Gate B 스킬 1개를 만들고, 별도 평가 3문제 × 3조건의 공식 채점 9회를 완료했다. 세 조건 모두 3/3 해결(100%)이며 해결률 차이는 0%p다.**

PDF 조건은 세 평가 문제 모두 실제 L3 스킬을 주입했다. 베이스라인도 전부 해결했으므로,
이번 표본에서는 스킬을 통한 추가 해결을 확인하지 못했다. 이전 실험의 66.7%와는 평가
문제가 다르므로 그 차이를 메모리의 효과라고 해석하지 않는다.

| 조건 | 공식 해결 | 해결률 | 베이스라인 대비 | 도구 요청 합계 | 실제 주입 | 주입 bytes |
| --- | ---: | ---: | ---: | ---: | --- | ---: |
| 메모리 없음 | 3/3 | 100% | 0%p | 38 | 0개 | 0 |
| 기존 M2 조회 | 3/3 | 100% | 0%p | 49 | 과거 경험의 공유 지식 3개 | 7,933 |
| PDF 기반 조회 | 3/3 | 100% | 0%p | 40 | L3 스킬 3개 | 3,552 |

주입 3개는 서로 다른 스킬 세 개를 뜻하지 않는다. **같은 검증 스킬 하나를 각 평가
세션에 한 번씩 제공한 것**이다. 도구 요청에는 조회·읽기·검색·수정·명령·오류·제출이
포함된다. 요청 수에서도 이번 실행의 PDF 조건은 베이스라인보다 2회 많았다.
한 번씩만 실행한 작은 표본이고 검사 범위와 병렬 부하도 달라 일반적인 효율 차이를
주장하지 않는다.

| 평가 문제 | 수정 대상 | 메모리 없음 | 기존 M2 | PDF 조회 | 도구 요청 A / B / C |
| --- | --- | --- | --- | --- | --- |

| SymPy 24562 | `Rational`의 문자열 인수를 곱하기 전에 변환 | 성공 | 성공 | 성공 | 14 / 16 / 15 |

9회 모두 풀이가 정상 제출됐고 기존 공식 SWE-bench grader가 성공으로 판정했다.
부분 제출이나 예산 소진으로 종료한 셀은 없다. 24562는 공식 이미지의 Python 3.9.20에서
검증했으며, 문제에서 언급한 Python 3.11 환경 자체를 별도로 재현하지는 않았다.

## 학습과 실제 승격

기존 학습 SymPy 23262·23413의 성공 기록을 보존하고, 새로운 24066·24213을 빈 메모리의
새 에이전트가 풀었다. 새 학습 두 개도 공식 채점을 통과했다.

| 새 학습 문제 | 내용 | 공개 검증 | 공식 판정 | 도구 요청 |
| --- | --- | --- | --- | ---: |
| 24066 | 무차원 함수 인자·지수의 차원 판정 | 수정 전 assertion 실패 → 같은 명령으로 32 passed, 1 expected failure | 성공 | 13 |
| 24213 | 덧셈에서 동등한 차원 인식 | 수정 전 assertion 실패 → 같은 명령으로 9 passed; 추가 단위 검사 72 passed, 1 expected failure | 성공 | 14 |

이번에는 관리자가 **공개 회귀 검증 절차를 학습 전에 정의**했다. 새 에이전트가 실제로
그 절차를 수행한 기록을 검증해 승격했다. 자동으로 새로운 일반 문제 해결 전략을
발견한 실험은 아니다.

승격 근거는 다음 실제 관찰이다.

1. 수정할 구현 파일과 기존 공개 테스트 모듈을 읽었다.
2. 첫 수정·명령 전에 파일과 정확한 테스트 명령을 등록했다.
3. 구현을 유지하고 새 assertion 회귀 테스트를 추가해 실패를 재현했다.
4. 테스트 파일을 유지하면서 구현을 수정했다.
5. 같은 명령이 통과했고, 그 코드 상태의 패치가 공식 채점도 통과했다.

명령 실행 전후의 파일·실행기·전체 패치 해시가 같아야 해당 검증을 인정한다.
마지막 통과 이후 파일을 바꾸면 승격 근거로 사용할 수 없다. 모델의 성공 주장이나
공식 문제 해결 여부만으로 절차의 실행을 추정하지 않는다.

실제 `SkillMemoryStore.record_episode()`와 `promote_skill()`을 호출했다. 서로 다른
작업·Codex 세션·검증 기록 두 개가 같은 매개변수화 절차를 지원한다. 이는 서로 다른
사람 두 명이 검증했다는 뜻은 아니다.

전체 학습 문제는 **4개**, 일반 Gate A 관찰은 **4개**, 공유 저장소 지식은 **4개**다.
새 학습 두 문제에 대한 절차 지원 관찰 2개가 별도 authority에 추가로 저장돼 있다.
이를 여섯 개의 독립적인 학습 문제로 세지 않는다. 실제 검증 스킬은 **1개**다.

## 평가에서 무엇을 조회했나

두 메모리 조건 모두 같은 네 개의 공유 지식과 같은 스킬 공개 내용을 조회 후보로
받았다. 스킬 공개 내용은 1,184 UTF-8 bytes이며, M2의 의미 기억과 PDF의 L3에 제공하는
내용이 정확히 같다.

M2는 24443·24562에서 과거 23262의 관찰을, 24539에서 과거 23413의 관찰을 선택했다.
새로 승격한 스킬은 M2의 실제 주입으로 이어지지 않았다. PDF controller는 세 문제
모두 L3 스킬을 우선 조회했다. 조회 결과를 보고 임계값이나 메모리를 조정하지 않았다.

이 스킬은 회귀 검증 절차다. 평가 문제별 수정 방법이나 모든 경계 조건에 대한 정답을
제공하는 스킬은 아니다. 원본 패치와 grader 전용 테스트 내용은 메모리에 넣지 않았다.

## 코드 버전과 실행 조건

원래 학습 경험의 조직·작성 주체·리비전과 승격 스킬의 원래 소유권을 유지한다.
기존 `SkillMemoryStore`의 버전 무효화 규칙은 수정하지 않았다.

공개된 절차를 다른 버전에서 제공하기 위해 별도 읽기 전용 투영을 사용한다.
평가 기준 코드의 `bin/test` 해시가 두 학습 실행기와 같고, 고정 이미지의 Python
3.9.20에서 기본 공개 테스트가 통과하는지 확인했다. 세 평가 환경 모두 기본 검사
22개를 통과했다. 인증서의 Python·이미지는 실제 평가 셀의 실행 조건과도 대조한다.
이 확인의 범위는 테스트 절차의 실행 조건이며 평가 버그 수정의 정확성은 아니다.

승격 결과를 실제 비폐기 SQLite 스킬 행과 지원 관찰의 메타데이터에 연결해 검사한다.
authority·선언·검증 기록·인증서의 해시를 고정하고 변경 시 조회를 차단한다. 개인 지원
경험의 원문을 평가 에이전트로 복사하지 않는다.

## 비교 조건과 해석 범위

- 모델 요청은 `gpt-6-astra`, reasoning 설정은 부모 설정을 동일하게 상속했다. 내부 날짜별 모델 snapshot은 독립적으로 증명하지 못했다.
- 새 학습 2회와 평가 9회에 `fork_turns="none"`의 새 세션 11개를 사용했다. 조건 간 풀이 힌트를 전달하지 않았다.
- 각 평가 셀은 별도 초기 checkout, 도구 요청 120회·첫 요청부터 1,200초, 메모리 최대 3개·12,000 bytes를 사용했다.
- 문제는 기존 개발·최종 평가·smoke와 이전 네이티브 실험을 제외한 공개 식별자 순서로 선정했다. 새 학습 2개와 새 평가 3개, 기존 학습 2개의 코드 선후 관계 17건을 확인했다. 새 패치가 과거 upstream에 병합됐다는 증명은 아니다.
- 초기 조회를 짧은 실제 문제 하위 목표와 공개 회귀 검증 작업으로 구성하고 모든 조건에 동일하게 적용했다. 이전 실험과는 질의 형식도 다르므로 이번 표본 안에서 조건을 비교한다.
- 별도 모델 API 호출은 **0회**다. Codex 사용량은 발생하며 정확한 토큰·비용은 관측하지 못해 `null`이다.
- L0는 Codex 기본 문맥을 사용한다. PDF의 하위 목표 문맥 교체는 적용하지 않았고, L2 지식 간선도 0개다. 전체 PDF 구조의 성능 입증으로 해석하지 않는다.

명령은 비관리자·네트워크 차단 컨테이너에서 실행했다. 새 에이전트의 호스트 도구
접근은 지정 중계기 사용 지침과 실제 기록·자기 확인으로 관리했다. OS 수준에서
모든 호스트 도구를 차단했다는 증명은 아니다.

이번 세 문제는 베이스라인부터 100%여서 추가 해결률을 구분하기 어려웠다. 다음 비교는
문제군과 선정 규칙을 먼저 고정하고, 관련 학습 사례와 새로운 평가 사례를 분리해
표본을 넓히는 것이 필요하다. 이번 성공 사례만으로 일반적인 해결률 상승을 주장하지 않는다.
