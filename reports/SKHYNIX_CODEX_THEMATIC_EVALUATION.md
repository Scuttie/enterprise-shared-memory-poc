공식 판정은 각 제출 패치의 실제 SWE-bench grader 결과다. 공개 테스트가 통과한 경우에도 공식 결과가
실패면 해결 수에 포함하지 않았다. 전체 공개 모듈이 통과하지 않은 사례와 검사 범위의 제한은
[에이전트별 검증 기록](../artifacts/skhynix_v1/codex_004/solver-attestations.json)에 보존했다.
도구 요청은 검색·읽기·수정·명령·조회·오류·제출을 포함한다. 검사 범위와 병렬 부하가 다르므로
요청 수나 시간의 차이를 곧바로 일반적인 효율 개선이라고 해석하지 않는다.
평가 18/18회가 에이전트의 완료 제출로 끝났고, 가장 많은 도구 요청은 37회였다.
이는 세션당 허용된 120회 이내다.

20916은 세 조건 모두 **숫자 자체가 유니코드인 접미사**를 놓쳤다. 그리스 문자와 보통 숫자의 조합은
공개 회귀 검사로 확인했지만 수학용 유니코드 숫자까지 일반화하지 못했다. 세 패치는 모두 정상 적용됐고,
인프라 장애 없이 같은 공식 검사 한 개에 실패했다. 해당 문제의 세 제출·채점이 모두 끝난 뒤 확인한
[실패 진단](../artifacts/skhynix_v1/codex_004/post-evaluation-failure-summary.json)이며,
이 결과로 패치나 기억을 수정하거나 풀이 세션에 힌트를 보내지 않았다.

21930은 세 조건 모두 생성 연산자의 중복 위첨자를 고쳐 공식 수정 대상 검사 6개 중 5개를 통과했으나,
같은 모듈의 텐서 출력에 필요한 그룹 괄호를 놓쳤다. 공개 문제는 생성 연산자의 최소 예시를 제시했고,
공식 검사는 텐서까지 포함했다. [모듈 내 수정 범위 누락 진단](../artifacts/skhynix_v1/codex_004/post-evaluation-failure-21930.json)을
같은 방식으로 세 조건의 채점 후에 기록했다. 기존 유지 대상 검사의 실패나 인프라 장애는 없었다.

22080은 세 조건 모두 수치 재현 예시를 고쳤으나, `Mod` 출력에 항상 괄호를 추가해 기존 단독 출력 형식을
바꾸고 음수 거듭제곱 전개 출력 요구를 놓쳤다. 공식 수정 대상 검사 3개 중 1개만 통과했고 유지 대상 검사도
1개 실패했다. [출력 계약 진단](../artifacts/skhynix_v1/codex_004/post-evaluation-failure-22080.json)에서
확인한 일부 실패는 생성 문자열의 정확한 형식 비교다. 이를 모두 수치 계산 오류로 해석하지 않는다.

## 학습과 스킬 전달

이번 은행에는 과거 실험의 기억을 재사용하지 않았다. 두 학습 문제 모두 빈 메모리의 새 에이전트가
풀었고, 각자의 실제 수정 전 assertion 실패·동일 테스트의 수정 후 통과·공식 채점을 확인했다.

| 학습 문제 | 공식 판정 | 도구 요청 | 제출 패치 SHA256 |
| --- | --- | ---: | --- |
| 14976 | 성공 | 19 | `c304c78a626813ff57177fc9f2fef4886ceb182552026c4ba6890a56f6d81b02` |
| 16766 | 성공 | 13 | `21ce2a9d874cc3a3cded6cc03da152bc2c0be23697e9aa76caa779685825bc6b` |

14976은 mpmath 유리수 코드 생성, 16766은 Python의 Indexed 출력 사례다. 일반 Gate A 관찰 2개와
공유 저장소 지식 2개가 만들어졌다. 별도의 절차 authority에는 같은 두 문제의 절차 검증 관찰이 들어갔다.
이를 네 개의 독립 학습 문제로 세지 않는다.

실제 Gate B가 사전에 정의한 공개 회귀 검증 절차 **1개**를 승격했다. 평가에서 사용할 수 있는 L3 스킬은 **0개**다.
학습 이미지의 공개 `bin/test`는 `optparse`를 사용하고, 여섯 평가 이미지에서는 `argparse`로 변경돼
실행기 파일의 해시가 달랐다. 두 환경의 Python은 모두 3.9.20이고 공개 기본 테스트도 통과했지만,
기존 호환성 검사가 스킬 전달을 차단했다. 이 검사를 완화하지 않았다.

사전에 선언한 대로 일반 관찰 은행의 바이트를 그대로 평가 은행으로 고정했다.
[스킬 전달 판정](../artifacts/skhynix_v1/codex_004/skill-compatibility-decision.json)과
[실제 승격 증거](../artifacts/skhynix_v1/codex_004/procedure-authority/promoted-procedure.json)를 보존했다.
두 메모리 조건의 후보 지식 본문은 같고 조회기가 선택과 기권을 결정했다. PDF 조회기의 JSON 포장으로
실제 주입 바이트 수는 M2와 다를 수 있다. 실제로 전달된 것은 학습 관찰이며, 승격 스킬의 효과를
측정한 결과는 아니다. KG 간선은 0개이고 Codex 기본 문맥을 사용하므로 전체 PDF 구조의 효과를 증명하지 않는다.
기억이 하나 이상 실제 전달된 문제는 기존 M2 6/6개,
PDF 조회 2/6개다.

## 표본 선정과 실행 조건

기존 학습 문제보다 뒤에 있는 미사용 SymPy 문제가 1개뿐이라 별도의 과거 학습·평가 묶음을 구성했다.
원래 DEV·heldout·smoke 및 native002·003에 속한 문제를 제외하고, 남은 SymPy 64개의 공개 식별자·제목·
기준 커밋·생성 시점을 살펴봤다. 관리자 LLM의 주제 판단으로 학습 2개와 평가 6개를 고른 뒤 고정했다.
선정에는 새 풀이 결과나 공식 테스트·정답 패치를 사용하지 않았다.

최초 학습 후보 18763의 기준 커밋은 여섯 평가 커밋의 조상이 아니었다. 풀이·채점·실행 계획 생성이
모두 0회인 시점에 이를 14976으로 교체했고, 평가 6개는 유지했다. 최초 계약과 실패한 계보 검사,
교체 근거를 [사전 변경 기록](../artifacts/skhynix_v1/codex_004/pre-execution-supersession.json)에 보존했다.
실제 Git 조상 관계 13개(학습→평가 12개와 학습 14976→16766 1개)가 모두 통과했다. 이는 기준 커밋의
계보 증거이며, 이번 에이전트 패치가 upstream에 병합됐다는 주장은 아니다.

- 요청 모델은 `gpt-6-astra`, reasoning 설정은 부모에게서 상속했다. 내부 날짜별 모델 snapshot은 별도로 증명하지 못했다.
- 문제×조건마다 `fork_turns="none"`의 새 에이전트와 별도 초기 checkout을 사용했다. 총 20개의 풀이 세션이다.
- 각 세션은 120회 도구 요청·첫 요청부터 1,200초, 최대 3회 기억 주입·12,000 UTF-8 bytes다. 하위 목표별 별도 요청 제한은 없다.
- 공통 프롬프트와 조회 문구는 native003과 같다. 은행·소스·평가 계획 6개(총 18셀)를 평가 전에 고정했고 평가 중 검색 기준이나 기억을 조정하지 않았다. 학습 계획은 별도 2개다.
- 요청 순서는 문제별 ABC / BCA / CAB / ACB / BAC / CBA다. 실제 가용 슬롯에 맞춰 같은 문제의 두 세션까지 병렬 실행했다. 시작 요청이 거절된 세션은 도구 실행 전에 대기했고 새 문맥으로 실행했다.
- 최종 8개 공식 이미지는 digest로 고정했고 각 공개 환경의 기본 테스트를 실행 전에 통과했다.
- 별도 모델 API 클라이언트 호출은 0회다. Codex 자체 사용량은 발생하며 정확한 토큰·비용은 측정되지 않아 `null`이다.

명령은 비관리자·네트워크 차단 컨테이너에서 실행한다. 에이전트에게 지정 중계기만 쓰도록 지시하고
실제 중계 기록과 자기 확인을 남겼다. 호스트 도구 전체를 OS 수준에서 막은 실험은 아니며,
기록되지 않은 모든 호스트 활동의 부재를 독립적으로 증명한 것은 아니다.

## 검증과 증거

관련 데이터 선정·집계·환경 검사 **115개**와 기존 동결 파일 **651개** 검사가 통과했다.
독립 감사 **5,842개** 검사가 통과했다. 결과는 [audit.json](../artifacts/skhynix_v1/codex_004/audit.json), 원본별 해시와 크기는
[공개 증거 목록](../artifacts/skhynix_v1/codex_004/public-artifact-manifest.json)에 있다.
공개 수집물에는 전체 패치·도구 대화·개인 경험 DB·비공개 채점 원문을 넣지 않았다. 원본은 로컬 WSL 실행 폴더에 보존했다.
중간 감사에서 중첩 필드와 PDF 조회의 직렬화 형식을 잘못 해석한 감사 코드 오류를 수정했다.
실패한 중간 감사도 보존했으며 실험 코드·은행·제출 패치의 변경은 없었다.
