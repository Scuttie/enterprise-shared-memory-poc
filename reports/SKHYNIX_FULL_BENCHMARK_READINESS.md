# SWE-bench Verified 전체 평가 준비 상태

후속 사용자 결정으로 본 비교는 [PDF 핵심 구조 OFF/ON](SKHYNIX_PDF_ARCHITECTURE_COMPARISON.md) 두 조건으로 변경했다. 아래는 Native011 종료 직후의 설정·규모 조사다. 새 설계의 500×2는 1,000회 문제 풀이이며 L0의 subgoal별 worker 교체 때문에 실제 native worker 수는 이보다 많을 수 있다.

Native011 완료 이후 설정과 데이터 범위를 읽기 전용으로 확인한 기록이다. 전체 평가의 실행 계약이 아니며, 이 조사에서 추가 솔버·공식 채점·컨테이너 실행은 하지 않았다.

현재 결과는 [Native011 상세 보고서](SKHYNIX_CODEX_CONTROLLED_TRANSFER_EVALUATION.md)와 [동결된 실행 계약](../artifacts/skhynix_v1/codex_011/launch-contract.json)에 있다.

고정 데이터는 500개 고유 문제, 12개 저장소다. 공개 메타데이터 열 `instance_id`, `repo`, `base_commit`, `created_at`만 읽어 집계했다. 정답 패치·채점 테스트 열은 이 조사에 사용하지 않았다. [공식 데이터 안내](https://www.swebench.com/SWE-bench/guides/datasets/)도 Verified의 규모를 500개로 명시한다.

500문제에 세 조건을 적용하고 모든 세션이 20분 상한을 사용하면 솔버 실행 시간의 합은 500시간이다. 두 조건이면 약 333.3시간이다. 이는 상한을 모두 사용하는 경우의 합계이며 실제 소요 시간 예측이 아니다. 환경 준비·채점·대기는 별도이고, 현재 관측된 동시 활성 솔버는 최대 2개다. Native011 12세션의 평균 약 167초는 네 문제의 관측치이므로 전체 작업 시간으로 일반화하지 않는다.

전체 평가에는 다음 변경이 필요하다.

1. 현재 데이터 등록기는 정확히 SymPy 네 문제와 두 분야별 두 문제 구성을 요구한다. 이를 보존하면서 여러 저장소와 임의 크기 목록을 지원하는 별도 실행 프로필이 필요하다. 현재 실제 네 ID가 코드 상수인 것은 아니며 manifest에 배정돼 있다.
2. 저장소별 기준 커밋·고정 컨테이너 이미지·공개 테스트 명령을 검증해야 한다. 현재 공개 실행 환경 검사는 SymPy import와 `bin/test --help`에 맞춰져 있다. 전체 500개 환경은 이번 조사에서 준비·검증하지 않았다.
3. 현재 두 교훈만으로 Django 등 다른 저장소의 문제마다 관련 교훈이 있다고 보장할 수 없다. 전체 메모리 시스템을 평가하려면 별도 학습 문제로 기억을 만든 뒤 은행·검색 규칙을 동결하고, 관련 기록이 검색되지 않은 경우도 그대로 평가해야 한다. 이 조건은 현재의 강제 전달 실험과 구분한다.
4. 현재 교훈을 유지하면 출처 두 문제는 새로운 문제로의 전이 지표에서 제외해야 한다. 전체 500개를 모두 전이 평가 대상으로 삼으려면 이 500개와 겹치지 않는 학습 출처가 필요하다. 기존에 개발·등록한 문제의 결과도 별도로 표시한다.
5. 대상 목록, 조건, 반복 수, 학습 출처, 검색 규칙, 예산, 실행 순서, 재개와 실패 처리 규칙을 실행 전에 동결한다. 풀이 결과를 보고 문제·교훈을 바꾸거나 실패를 분모에서 빼지 않는다. 기반 환경의 실패는 솔버 실패와 구분해 전체 예정 수와 함께 공개한다.

권장 주 비교는 동일한 모델·도구·예산의 A 메모리 없음과 C 동결한 기억 은행의 자동 검색이다. B의 다른 분야 교훈 대조는 추가 비교로 사전 지정할 수 있다. 현재 +25%p는 강제 전달한 네 문제의 탐색 결과이며, 이 전체 실행 설계의 결과는 아직 없다.
