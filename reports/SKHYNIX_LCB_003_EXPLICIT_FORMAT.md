# 공통 제출 규칙을 명시한 Luna 메모리 OFF/ON 평가

2026-09-24 완료. **공통 제출 규칙을 충분히 안내한 뒤 처음부터 풀게 한 결과, OFF는 24/24(100%), ON은 22/24(91.7%)였다. ON−OFF는 −8.3%p이며, 이번 조건에서 정답률 상승은 관측되지 않았다.** 양쪽 모두 첫 제출부터 규약을 준수했으며 미제출·형식 오류·인프라 보류는 0건이다. 이전의 제출 단계 전용 KEEP/DROP 144세션 실험과 별개의 전체 풀이 실험이다.

코드·조건은 `24a277d04609ae1be3c5747ff85b96629c6f9583`에서 커밋·push한 뒤 실행했다. 12:43 KST에 시작하여 13:01 KST에 완료를 확인했으며, manager 측정 총 소요 시간은 **17분 49.4초**였다. 실제 모델 작업은 48개 셀·49개 새 세션, 공식 채점은 48개 후보이며 추가 학습·재시도·TEST 실행은 없었다.

### 기억이 실제로 쓰였는가

OFF의 기억 주입은 0회다. ON은 **24문제 중 22문제에 L1 28회, 고유 경험 7개**가 주입됐다. L2/L3의 실제 주입은 0회다. 저장소에는 L2 관계가 있지만 이번 검색에서 노출되지 않았으며, L3 검증 절차는 원래 0건이다. 따라서 현재 고정된 9개 TRAIN 경험과 조회 정책의 효과를 평가한 것이며, 충분한 L2/L3 기억을 사용하는 전체 PDF 구조의 효과를 평가했다고 표현하지 않는다.

이전의 큰 상승을 일반적인 알고리즘 문제 해결 능력 향상으로 해석하면 안 된다. 이번에는 안내를 완전히 준 상태에서 OFF도 전부 제출했고, 메모리의 추가 정답률 이득은 남지 않았다. 다만 위 두 행은 새 세션에서 별도로 생성한 결과이므로 OFF의 12개 증가 전부를 안내 변경만의 효과로 배분하지 않는다. [KEEP/DROP 실험](SKHYNIX_LCB_FORMAT_ABLATION.md)은 불완전한 공통 안내 아래에서 기억 속 형식 예시가 제출 준수에 기여했다는 더 좁은 근거로 유지한다.

이 결과를 확인한 뒤 성공할 때까지 반복하거나 문제·기억·채점 기준을 바꾸지 않았다. 다음 일반화 평가가 필요하면 명시적 제출 규칙을 유지하고 별도로 고정한 TRAIN 경험, 아직 쓰지 않은 문제, 사전에 정한 반복 수로 새 실험을 설계해야 한다.

문제 ID·실행 순서·예산·은행 해시는 [설정 파일](../configs/skhynix_v1/lcb_003_explicit_format.json)에 고정했다. OFF 먼저 12쌍, ON 먼저 12쌍으로 예약 순서를 맞춘다. 두 worker가 겹쳐 실행되므로 시작/완료 시각도 따로 기록한다. 모델 무작위 seed는 고정하지 못한다. 1회 48개 비교를 사전에 정했으며, 결과에 따라 반복 수를 늘려 좋은 결과만 선택하지 않는다.

## 형식 안내의 공정성

양쪽에 `source_lesson`의 네 필드와 정확한 타입, `trace_steps`의 비어 있지 않은 정수 목록·오름차순·중복 금지·현재 대상 history에 존재해야 한다는 규칙을 동일하게 명시한다. 성공한 graph 수정·공개 테스트·하위 과제 완료 기록을 모두 인정하며, 공개 테스트 번호만으로 제한하지 않는다. 실제 공개 테스트를 최소 한 번 실행해야 한다는 별도 조건도 설명한다.

합성 예시의 번호와 다른 TRAIN 문제의 번호를 대상 문제에 그대로 복사하면 안 된다고 명시한다. 세션을 전환해도 같은 계약 안내와 현재 사용 가능한 번호가 다시 제공된다. 기존 validator와 성공 조건은 바꾸지 않고, 자동 형식 수정이나 실패 후 추가 예산도 주지 않는다.

기존 full-solve native broker는 이미 binary UTF-8 JSON 입출력을 사용한다. CP949 환경에서 한글·비ASCII가 포함된 합성 요청을 실제 subprocess로 전달하는 회귀 검증도 수행한다. 이전 제출 전용 실행기의 인코딩 결함을 이번 경로에 가져오지 않는다.

## 성적과 채점 순서

주 지표는 **정상 최종 제출 AND 공식 비공개 테스트 통과**다. 모델의 미제출·규약 위반·명시된 예산 초과는 실패로 센다. 원인이 확인되지 않은 실행/채점 인프라 오류는 null로 남기고 분모와 보류 건수를 명시한다. 같은 ID의 OFF/ON 결과를 짝지어 비교한다.

보조 지표는 정상 제출률, 첫 제출 및 전체 제출 형식 오류, 시간·토큰·공개 테스트 수·실제 메모리 주입량, 제출 여부와 분리한 보관 코드의 정답성이다. 미제출 사례의 코드는 **마지막으로 기록에 결속된 비어 있지 않은 rejected finish 코드**, 없으면 **마지막 성공한 공개 테스트 동작의 후보**를 선택한다. 원본 바이트를 유지하고, 코드가 없으면 `NOT_AVAILABLE`로 기록한다. 채점 결과를 보고 더 좋은 후보를 고르지 않는다.

48개 풀이와 보조 후보 선택을 모두 봉인한 후에만 비공개 채점을 시작한다. 정상 제출 사례는 본 채점 결과를 보조 지표에도 재사용하고, 미제출 원본 후보만 별도로 채점한다. 보조 채점으로 본 성적을 덮어쓰지 않는다. 비공개 결과를 solver나 메모리에 보내지 않는다. 중단된 모델 시도를 자동으로 다시 풀지 않는다.
