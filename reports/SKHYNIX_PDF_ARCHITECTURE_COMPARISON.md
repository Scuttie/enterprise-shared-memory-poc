# PDF 핵심 메모리 구조 ON/OFF 비교

사용자의 수정에 따라 본 실험은 **같은 에이전트의 일반 문맥 기준선과 PDF 핵심 메모리 구조를 적용한 에이전트**를 비교한다. Native011의 수동 교훈 배정 비교는 별도 탐색 결과로 남긴다. Native011의 +25%p를 이 구조 비교의 결과로 사용하지 않는다.

여기서 **학습은 모델 가중치를 바꾸는 fine-tuning이 아니라, 실제 풀이 기록으로 외부 메모리를 만드는 과정**이다. 모델은 코드 수정과 공개 테스트를 수행하고, 별도 새 세션이 그 기록에서 재사용 가능한 절차를 제안한다. 경험·저장소 관계·검증된 스킬은 외부 bank에 저장한다. PDF는 메모리 구조의 설계 자료이고, 학습과 평가의 실제 입력은 Python 오픈소스 저장소의 코드 수정 문제다.

| 단계 | 사용하는 자료 | 모델·실행 | 만들어지는 결과 |
| --- | --- | --- | --- |
| 메모리용 경험 수집 | 원본 SWE-bench의 `test` split에서 이번 평가와 겹치지 않게 고른 24문제 | `gpt-6-astra`; 1~8번은 기존 `ultra`, 9~24번은 `high`; 빈 bank에서 새 native 세션으로 풀이 | 공개 실패·수정·테스트 기록과 하위 목표별 요약 |
| 경험 정리·검증 | 위 24문제의 공개 실행 기록 | 새 `gpt-6-astra / high` reflection 세션, 이후 코드로 근거·승격 요건 검증 | L1 개인 경험, L2 저장소 관계, L3 검증 스킬을 포함한 고정 bank |
| 본 평가 | 고정된 SWE-bench Verified `test` 전체 500문제 | 두 조건 모두 `gpt-6-astra / high`, 같은 문제를 조건별 한 번씩 총 1,000회 풀이 | 조건별 제출 패치와 실행 기록 |
| 공식 채점 | 제출을 마친 각 조건의 패치 | 고정된 공식 SWE-bench 채점 실행 경로 | 문제별 `resolved`와 전체 해결률, PDF−기준선 차이 |

원본 데이터의 split 이름이 `test`여도 위 24개는 **이번 실험에서는 메모리 학습용**으로 명시적으로 등록했다. 현재 학습 24개와 평가 500개의 instance ID 및 문제 설명 해시는 겹치지 않는다. 학습 문제를 다시 푸는 성능보다, **같은 저장소의 다른 문제에서 얻은 경험이 별도 문제 해결에 도움이 되는지**를 측정한다. 학습과 평가가 저장소 자체까지 분리된 실험은 아니다.

24개 학습 시도가 24개 성공이나 24개 검증 스킬을 뜻하지는 않는다. 실패·미검증 경험도 보존하며, 공유 스킬은 서로 다른 문제·합성 소유자의 실제 공개 실패→구현 수정→같은 공개 테스트 명령 성공 근거를 확인한 경우에만 승격한다. 필수 검증 스킬이 없으면 현재 파이프라인은 본 평가 전에 중단한다.

공식 `resolved` 판정은 제출 후 실행한 고정 채점기의 FULL resolution이다. 지정된 FAIL_TO_PASS 테스트를 모두 통과시키고 PASS_TO_PASS 테스트의 통과도 유지해야 한다. 모델의 완료 선언이나 풀이 중 일부 공개 테스트 성공만으로 해결 처리하지 않는다. 공식 채점 결과를 해당 풀이에 되돌려 재시도하지 않는다.

현재 단계는 **실제 학습 실행**이다. 평가와 겹치지 않는 학습 24개를 고정했으며 새 native 세션의 풀이와 공식 채점을 진행하고 있다. 하위 목표 전환 시 실제 세션 교체와 도구 호출을 확인했다. 학습 bank 동결 후 전체 500문제의 A/C 평가가 이어지는 순서다. 최신 진행과 설정 변경의 정확한 적용 지점은 [실제 실행 기록](SKHYNIX_PDF_ARCHITECTURE_EXECUTION.md)에 있다. 아래 초기 준비 검증 수치는 당시의 기록이며 본 비교의 해결률이 아니다.

| 항목 | A: BASELINE | C: PDF_MEMORY |
| --- | --- | --- |
| 공통 에이전트 | 같은 모델·계획 및 코드 도구·공개 테스트·공식 채점기 | 동일 |
| 현재 작업 문맥 | 공통 상한 안의 일반 대화·도구 이력 | L0: 현재 subgoal 상세 이력과 완료 subgoal의 근거 있는 요약 |
| 과거 상세 이력 | 일반 이력 정책으로 제공 | task/subgoal에 묶인 명시적 원문 복구 |
| 세션 간 개인 기억 | 사용하지 않음 | L1: 같은 소유자의 성공·실패·수정 경험 |
| 저장소 지식 | 별도 memory 조회 없음 | L2: 출처와 관계가 있는 저장소 KG |
| 공유 절차 | 별도 memory 조회 없음 | L3: 실제 검증·일반화·parameterisation을 통과한 Skill Library |
| 조회 | 빈 memory 결과 | metadata 범위 검사 후 Skill → Repo KG → 개인 경험 |
| 새 경험 | 감사용 실행 기록만 유지 | Gate A로 개인 경험을 저장하되 평가용 고정 bank에는 합치지 않음 |

일반 대화 이력과 감사 로그까지 없애는 기준선이 아니다. PDF가 추가하는 문맥 관리와 지속 메모리 경로를 켜고 끄는 비교다. 같은 문제의 양쪽에 동일한 문제 설명, 기준 커밋, 코드·명령 도구, 테스트 접근 및 예산을 적용한다. 문제별 교훈의 직접 배정, 정답에 맞춘 검색 우회, 다른 분야 교훈 B 조건은 본 비교에서 사용하지 않는다. 검색 결과가 비어 있거나 도움이 되지 않은 경우도 결과에 포함한다.

주 지표는 PDF 메모리 시스템을 도입했을 때의 전체 효과다. 두 조건은 같은 계획·worker 전환 실행기를 공유하므로 별도 SWE-bench 리더보드의 기본 에이전트와 직접 비교하는 설정은 아니다. L0, L1, L2, L3 각각의 기여를 분리하려면 본 비교 이후 별도 제거 실험이 필요하다.

PDF 원문은 `LLM_Agentic_Memory_SKhynix_v1.pdf`이며 SHA-256은 `48cf59041ca5cedce430cc3237c418e03c2955948f1af0ed26002d8ab48f941d`다. 32쪽과 42–46쪽을 다시 대조했다. L0의 상세 이력 숨김·복구, Gate A의 개인 경험, 관계가 있는 L2, Gate B로 승격한 parameterised L3와 무효화가 핵심이다. 46쪽의 학습된 정책은 후속 단계이므로 1차 비교는 명시적으로 고정 규칙을 사용한다. 로컬 구현을 production 인증·DB·CI 갱신 서비스까지 포함한 배포 시스템으로 표시하지 않는다.

실행 설계의 공통 조건은 다음과 같다.

- 평가: 고정된 SWE-bench Verified **전체 500문제**, A/C 각각 한 번, 총 **1,000회 문제 풀이**. 기존 개발·등록 문제도 포함한다는 사실을 별도로 보고하며 전역적으로 처음 본 문제라고 주장하지 않는다.
- 모델: `gpt-6-astra` 요청. 2026-09-14 사용자의 변경 요청에 따라 **본 평가 A/C 모두 reasoning effort `high`**로 고정한다. 전환 전에 시작한 학습 문제는 원래 `ultra` 기록을 보존하고, 이후 학습과 공개 기록의 reflection에는 `high`를 적용한다. 학습 출처의 effort를 개별 기록하며 이전 결과를 다시 풀거나 `high` 결과로 바꾸지 않는다. 별도 모델 API를 사용하지 않는 native worker 방식이며 요청 모델과 백엔드 독립 검증을 구분한다.
- 예산: 문제·조건당 전체 worker를 합쳐 도구 요청 120회, 첫 요청부터 1,200초. subgoal 전환으로 예산을 초기화하지 않는다. 같은 전체 packet 상한 196,608 UTF-8 바이트와 이력 상한 48,000바이트를 적용한다. C의 메모리 주입은 최대 3건·12,000바이트이며 전체 상한에 포함한다. 모델 토큰·비용을 측정하지 못하면 미계측으로 남긴다.
- 문맥 전환: 양쪽 모두 같은 subgoal 완료 규칙에서 새 native worker를 시작한다. A는 일반 이력, C는 PDF 문맥 projection을 전달한다. 새 worker에는 이전 대화를 상속하지 않는다. 따라서 **1,000회 문제 풀이와 native worker 1,000개는 같은 수량이 아니다.** 실제 worker 수는 전환 횟수에 따라 늘어난다.
- 학습: 평가 500문제와 겹치지 않는 별도 자료에서 실제 실행 기록을 만든다. 기존 Native 학습 문제와 Native011 수동 교훈은 이 500문제에 포함되므로 새 bank에 재사용하지 않는다.
- 동결: 학습 기록·지식 관계·검증 스킬·조회 및 무효화 규칙을 평가 전에 고정한다. 평가 중 생성한 경험은 별도 보관하고 다른 평가 문제로 전달하지 않는다.
- 지표: 공식 문제 해결률과 C−A의 대응 비교가 주 지표다. 저장소별 결과, 실제 조회 계층·전달률, 도구 요청, 시간, 문맥 바이트를 추가로 기록한다. 일부 전달 성공 사례만 골라 전체 결과로 보고하지 않는다.

각 평가 문제를 A/C에서 모두 풀므로 마지막 열의 두 배가 실제 풀이 횟수다. 전체 해결률의 분모는 조건별 500이며, 두 조건의 점수를 합쳐 1,000을 분모로 사용하지 않는다. 예를 들어 A가 300개, C가 320개를 해결했다면 60% 대 64%, 차이는 +4%p다. 이 숫자는 지표 설명을 위한 예시이며 실제 결과가 아니다. Django가 전체의 46.2%이므로 저장소별 결과도 함께 해석한다.

정확한 instance ID·기준 커밋·공개 생성 시각은 [학습 24개 전체 목록](SKHYNIX_PDF_ARCHITECTURE_TRAINING_24.csv)과 [평가 500개 전체 목록](SKHYNIX_PDF_ARCHITECTURE_EVALUATION_500.csv)에 있다. 두 파일은 고정된 [실행 데이터 manifest](../configs/skhynix_v1/architecture_001_dataset.json)에서 공개 메타데이터만 추출한 열람용 목록이며, 원래 실행 설정을 변경하지 않는다.

구현 연결 상태와 남은 실제 검증은 다음과 같다.

| 구성 | 확인한 상태 | 완료 조건 |
| --- | --- | --- |
| L0 | 새 broker에 연결, 실제 planner→첫 목표→다음 목표에서 새 세션 교체 확인 | 전체 A/C 실행의 문맥·복구 사용 기록 |
| L1·Gate A | 학습 공개 이력 수집과 소유자별 저장 adapter 검증 완료, 빈 학습 authority 초기화 | 실제 학습 경험 수집·조회, 평가 기록 격리 |
| L2 | 출처 파일·행 범위·공동 관측 관계 수집 및 revision 검사 구현 | 실제 bank의 관계 수와 평가 대상에서 유효한 조회율 |
| L3·Gate B | 실제 RED→편집→동일 GREEN, 서로 다른 출처·소유자 검증 및 승격 경로 구현 | 새 학습 자료에서 실제로 승격한 절차와 조회 결과 |
| 전체 실행기 | 전체 목록·524개 이미지 digest·공개 실행 환경·공식 채점 연결, native 실행 중 | 실제 공식 채점 및 전체 500쌍 결과 |

현재 native 대화에 요약 문자열을 추가하는 것만으로는 이미 본 상세 이력이 숨겨지지 않는다. 새 문맥 packet 생성 검사와 실제 native 실행 경로 연결 검증을 구분한다. graph의 부가 메타데이터를 통해 완료된 raw 이력이 새 packet에 다시 포함되지 않는지도 확인한다.

초기 기반인 [native_architecture_context.py](../src/enterprise_memory/trimem/native_architecture_context.py)는 두 조건의 초기·subgoal 전환 packet을 구성하고, task·arm·worker·설정·bank·이력의 바인딩을 검사한다. 완료 subgoal의 원문은 명시적으로 조회하며, 응답 상한을 넘는 큰 관측도 원본 행 SHA와 바이트 조각으로 정확하게 복구할 수 있다. 이 기반의 초기 테스트는 **115개**를 통과했다. 이후 실제 worker 교체·전체 예산 집행·native 입장·공식 채점을 연결한 실행기가 추가되었다.

개인 기억은 학습 worker 전부의 내용을 한 사용자에게 합치지 않는다. 합성 소유자별 이력을 유지하고, 다른 소유자에게 전달되는 절차는 Gate B를 거친다. 합성 contributor ID를 실제 여러 사람의 독립 증거로 표현하지 않는다. 과거 저장소 지식과 스킬에 현재 revision 라벨만 붙여 유효하다고 처리하지 않는다. 출처 revision과 현재 적용성 근거를 보존하며, stale 자료는 조회에서 제외한다.

평가 inventory는 [architecture_verified500_inventory.json](../configs/skhynix_v1/architecture_verified500_inventory.json)이다. Parquet의 공개 식별자·문제 설명 열만 읽었으며 inventory에는 문제 본문 대신 `problem_statement.strip()`의 SHA-256을 저장했다. 500개 전체 inventory SHA-256은 `437d84f2e76eaa8a2293788b7bebb0f86dbf27cd6e4acb9a6b855d4e19ac7f77`다.

학습 후보는 [별도 후보 inventory](../configs/skhynix_v1/architecture_training_candidates_inventory.json)에 고정했다. 원본 SWE-bench의 dev 225개와 test 2,294개를 확보하고 공개 열로 중복을 조사했다. 데이터 출처와 열 정의는 [고정 revision의 공식 데이터 설명](https://huggingface.co/datasets/SWE-bench/SWE-bench/raw/c6fe717fd7a4c3ac1daa4055a4fd082c6a1d28a2/README.md)에 있다. 평가와 같은 12개 저장소의 ID 비중복 후보 1,794개 중 문제 설명 해시가 평가와 같은 8개를 추가로 제거해 **1,786개**를 남겼다. 이 수는 학습을 완료한 문제 수가 아니라 선택 가능한 후보 수다. 후보 inventory SHA-256은 `b92a1399cc5c51882e48449f508a6609ae82df4c7e0816f4f198cc135d83a8a5`다.

ID와 설명 해시 중복을 제거한 사실만으로 시간 순서나 모든 의미상 중복까지 검증했다고 주장하지 않는다. `created_at`은 PR 생성 시각이며 커밋의 조상 관계가 아니다. 최종 학습 출처 선택과 revision 적용성 검증은 별도로 남아 있다.

실제 준비 설정은 [architecture_001_preparation.json](../configs/skhynix_v1/architecture_001_preparation.json)이며 SHA-256은 `6454391df77910daf5102be056a420207b0b154eb10a465422f1f719e54224f5`다. 설정 검사는 A/C의 공통 예산, 정확한 전체 500개 목록, 학습 후보와의 ID·설명 해시 분리, 준비 완료 상태의 오표시 거부를 포함해 **57개**를 통과했다. 설정 상태는 `NOT_EVALUATION_READY`다.

[준비 증거 요약](../artifacts/skhynix_v1/architecture_preparation_001/summary.json)과 [준비 상태](../artifacts/skhynix_v1/architecture_preparation_001/readiness.json)에 실제 결과를 보관했다. 준비 증거 30개에는 설정·공개 자료 조사·검증한 소스·최종 및 초기 테스트 기록이 포함되며, [공개 파일 목록](../artifacts/skhynix_v1/architecture_preparation_001/public-artifact-manifest.json)의 SHA-256은 `57531b94b09983180388782e4455d41599e999de292ccf89624f292442a2391a`다. 최종 테스트는 합계 **172개 통과, 실패·오류·skip 0**이다. 기존 Native011 공개 증거 251개의 바이트도 그대로 유지했음을 확인했다. 준비 검사 통과는 live 솔버 연결이나 벤치마크 해결률 결과를 뜻하지 않는다.

데이터 규모·물리 디스크·기존 실행 환경에 대한 최초 확인은 [전체 평가 준비 상태](SKHYNIX_FULL_BENCHMARK_READINESS.md)에 있다. 전체 이미지를 한꺼번에 보관하는 대신 기존 실행기의 목표별 준비·해제와 실제 호스트 디스크 하한 검사를 사용한다. 실제 학습 bank 및 live runtime 검증이 없으면 전체 평가 시작 조건을 만족한 것으로 표시하지 않는다.
